## 표

- 행은 비교 대상, 열은 속성. 열은 3~6개까지. 넘으면 표를 나누거나 덜 중요한 열을 접힌 세부 표로 보낸다.
- 단위는 머리글에 한 번만 쓴다("정확도 (%)"). 숫자는 오른쪽 정렬, 소수 자릿수를 맞춘다.
- 강조는 표 하나에 한 종류만(예: 열마다 최고값 굵게).
- 행 순서에 뜻을 둔다. 알파벳순보다 "기준선 → 기존 방법 → 제안 방법" 또는 값의 크기순.
- 칸에 문장이 들어가기 시작하면 표가 아니라 글로 써야 한다는 신호다.

## 차트

아래 내용으로 대부분의 차트는 충분하다. 색 체계를 새로 정해야 하거나 낯선 종류의 차트라면 차트 전용 스킬(dataviz 등)이 있는지 보고 읽는다.

**종류 고르기**

| 보여 줄 것 | 종류 |
|---|---|
| 항목 간 크기 비교 | 막대 (항목 이름이 길면 가로 막대) |
| 순서가 있는 축 위의 변화 (task, epoch, 예산) | 선 |
| 두 값의 관계, trade-off | 산점도 |
| 분포, seed 간 흩어짐 | 점 + 오차 막대, 상자 그림 |
| 대상 × 조건 격자의 값 | 히트맵 (칸에 값을 적는다) |

**만들 때**

- 범례 대신 선이나 막대 옆에 이름을 직접 적는다. 눈이 범례와 그림 사이를 오가지 않아도 된다.
- 주장과 관련된 계열 하나만 색을 주고 나머지는 회색으로 둔다.
- 막대 차트의 값 축은 0에서 시작한다. 잘라내면 차이가 과장된다.
- 반복 실험이면 평균만 그리지 말고 흩어짐(오차 막대나 개별 점)을 같이 그린다. 몇 번 반복했는지 캡션에 쓰고, 반복이 적으면 몇 번 중 몇 번이 같은 방향인지를 라벨이나 캡션에 말로도 적는다.
- 그림 하나에 메시지 하나. 기준선, 부호 표시, 보조 계열을 한 그림에 겹쳐 넣기 시작하면 그림을 나누거나 덜 중요한 것을 뺀다.
- 그림 안의 글자는 화면에 표시되는 크기에서 읽혀야 한다. 큰 캔버스에 그려 축소해 넣으면 라벨이 8~9px가 되어 읽히지 않는다.
- 축 이름에 단위를 쓴다. 제목은 주장 문장으로 쓴다.

**matplotlib**

```python
import matplotlib
matplotlib.use("Agg")
import matplotlib.pyplot as plt

plt.rcParams["font.family"] = "Noto Sans CJK KR"   # 한글 라벨을 쓸 때. `fc-list :lang=ko`로 설치 여부 확인
plt.rcParams["axes.unicode_minus"] = False

fig, ax = plt.subplots(figsize=(6.4, 3.6), dpi=200)
...
ax.spines[["top", "right"]].set_visible(False)
fig.savefig("fig.svg", bbox_inches="tight")        # 페이지에 넣을 때는 SVG, 채팅·슬라이드용은 PNG
```

한글 폰트가 없으면 글자가 네모로 깨진다. 그럴 때는 그림 안의 라벨은 영어로 쓰고 캡션을 한글로 쓴다.

HTML 페이지에 넣을 때는 SVG를 그대로 붙이거나 PNG를 base64로 넣어 파일 하나로 열리게 한다.

## 다이어그램

구조·흐름·관계·인과를 보여 줄 때 쓴다. 아래 규칙으로 부족할 만큼 복잡한 그림이면 다이어그램 전용 스킬이 있는지 보고 읽는다.

- 상자는 대략 일곱 개까지. 넘으면 묶어서 한 단계 위의 그림을 먼저 보여 주고, 필요한 부분만 따로 확대한다.
- 흐름은 한 방향으로(왼쪽→오른쪽 또는 위→아래). 화살표가 되돌아가는 곳은 그것이 요점일 때만.
- 화살표에는 무엇이 넘어가는지 적는다("토큰 197개", "gradient"). 라벨 없는 화살표는 "관련 있음" 이상의 정보를 주지 못한다.
- 상자 안에는 이름과 한 줄 역할만. 설명은 그림 아래 글로 뺀다.
- 색은 구분에 뜻이 있을 때만 쓴다(예: 고정된 부분은 회색, 학습되는 부분은 색). 무엇을 뜻하는지 그림 안에 적는다.
- 실제 구조를 그린다. 코드나 설정을 확인하지 않고 "보통 이렇다"로 그린 다이어그램은 틀린 설명을 선명하게 만들 뿐이다.

**무엇으로 그릴까**: 페이지 안이면 인라인 SVG가 가장 안정적이다. Mermaid는 렌더되는 곳(GitHub, 일부 문서 도구)에 낼 때만 쓰고, 터미널이나 일반 채팅에는 코드 그대로 보이므로 쓰지 않는다.

## 그림·예시 모음

모델 출력, 시각화 결과, 실패 사례처럼 "실제로 어떻게 보이는지"를 보여 줄 때.

- 같은 크기의 격자로 배열하고, 행과 열에 뜻을 둔다(행 = 입력, 열 = 방법).
- 캡션에 무엇을 봐야 하는지 쓴다("3번째 열에서 배경 토큰이 먼저 합쳐진다").
- 잘 나온 것만 고르지 않는다. 대표적인 예와 실패한 예를 함께 두고, 어떻게 골랐는지 적는다.
- 예시는 주장의 근거가 아니라 주장을 이해시키는 보조 자료다. 수치 근거와 같이 둔다.

## 인터랙티브 HTML

독자가 조건을 바꿔 가며 보고 싶어 하거나(데이터셋, seed, 방법 선택), 한 번에 다 펼치면 너무 많을 때 쓴다.

- **처음 열린 상태가 곧 답이다.** 기본 선택값은 가장 중요한 뷰로 두고, 아무것도 누르지 않아도 핵심이 읽혀야 한다.
- 조작 요소는 세 개 이하. 탭, 선택 버튼, 접기 정도면 대부분 충분하다. 슬라이더는 값이 연속일 때만.
- 조작하면 무엇이 바뀌는지가 바로 눈에 보여야 한다. 바뀌는 부분 근처에 조작 요소를 둔다.
- 접힌 세부는 `<details>`로 충분하다. 직접 만든 아코디언보다 안정적이고 인쇄·검색도 된다.
- 파일 하나로 열리게 한다. 외부 CDN 없이 순수 JS로 쓰고, 데이터는 `<script type="application/json">`에 넣는다. 며칠 뒤 오프라인에서 다시 열어도 그대로 보인다.
- 좁은 화면에서도 가로 스크롤 없이 읽히는지 본다. 밝은 배경과 어두운 배경 모두 확인한다.

`assets/page-template.html`에 결론 상자, 개요 표, 주장 제목이 붙은 그림, 접힌 세부, 용어 목록의 기본 모양이 있다. 복사해서 내용을 채우고 쓰지 않는 블록은 지운다.

## 애니메이션과 동영상

상태가 시간에 따라 변하는 과정에만 쓴다. 알고리즘이 단계별로 진행되는 모습, 토큰이 층마다 합쳐지는 과정, task가 늘어남에 따라 정확도가 무너지는 모습 같은 것. 전/후 두 장을 나란히 놓아서 충분하면 그렇게 한다. 정지 그림은 독자가 자기 속도로 볼 수 있다.

**먼저 고려할 것: 페이지 안의 단계별 재생**

이전/다음/재생 버튼과 "지금 무슨 단계인지" 한 줄 설명이 붙은 그림. 독자가 멈추고 되돌릴 수 있어서 동영상보다 이해에 유리하다. 단계마다의 상태를 배열로 두고, 버튼이 인덱스를 바꾸면 SVG를 다시 그리는 방식이면 된다.

**동영상 파일이 필요할 때** (슬라이드에 넣기, 메신저로 공유)

- 길이는 10~30초. 단계 이름을 프레임 안에 적는다. 소리 없이도 이해돼야 한다.
- 한 단계에 최소 1초는 머문다. 마지막 상태에서 2초 멈춘다.
- 동영상만 주지 않는다. 결론 한 줄과 핵심 프레임 한 장을 같이 준다.

```python
import matplotlib
matplotlib.use("Agg")
import matplotlib.pyplot as plt
from matplotlib.animation import FuncAnimation, FFMpegWriter

steps = [("1단계: ...", data1), ("2단계: ...", data2), ("결과", data3)]
FPS, HOLD = 12, 12                      # 단계마다 HOLD 프레임(= 1초) 머문다

fig, ax = plt.subplots(figsize=(6.4, 3.6), dpi=200)

def draw(i):
    label, data = steps[min(i // HOLD, len(steps) - 1)]
    ax.clear()
    ...                                  # data를 그린다. 축 범위는 고정해야 화면이 흔들리지 않는다
    ax.set_title(label, loc="left")

frames = HOLD * len(steps) + 2 * HOLD   # 마지막 상태에서 2초 정지
FuncAnimation(fig, draw, frames=frames).save(
    "out.mp4",
    writer=FFMpegWriter(fps=FPS, codec="libx264", extra_args=["-pix_fmt", "yuv420p"]),
)
```

`yuv420p`를 빼면 일부 플레이어와 브라우저에서 재생되지 않는다. `ffmpeg`가 없으면 `which ffmpeg`로 확인하고, 없을 때는 단계별 재생 페이지로 대신한다.

GIF가 필요하면 mp4에서 변환한다.

```bash
ffmpeg -y -i out.mp4 -vf "fps=12,scale=640:-1:flags=lanczos,split[a][b];[a]palettegen[p];[b][p]paletteuse" out.gif
```

이미 저장해 둔 프레임 이미지가 있으면 바로 묶는다.

```bash
ffmpeg -y -framerate 12 -i frames/%04d.png -c:v libx264 -pix_fmt yuv420p out.mp4
```
